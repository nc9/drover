---
title: Untrusted data
description: Fence everything that did not come from the operator, so outside text reaches the model as data, not instructions.
---

**Invariant: anything that did not come from the operator's own prompt or code is
untrusted until positively marked trusted, and derived text inherits the least
trusted input.** Drover's fence plugin is built on that, and fails closed: every
bookkeeping miss over-fences, none can under-fence.

An agent that reads outside text (web pages, emails, tickets, shell output, MCP
results, other agents' answers) can be told what to do by that text. The **fence**
is a tagged block with a per-run random nonce, plus cleaning that stops a value
from closing or opening a tag. The model is told in the system prompt that
everything inside a fence is data whatever it claims.

```ts
import { defineAgent } from "@droveragent/core";
import { truncatePlugin, untrustedResultsPlugin } from "@droveragent/plugins";

// One allowlist, owned by the fence plugin: tools whose output is the operator's own.
const fence = untrustedResultsPlugin({ trusted: ["clock"] });
const truncate = truncatePlugin({ isTrusted: fence.isTrusted }); // reads the same list

const spec = defineAgent({
  id: "page-reader",
  systemPrompt: "You summarise pages.", // no fence note to remember: the plugin adds it
  tools: ["fetch_page", "bash"],
  plugins: [truncate.plugin, fence], // fence after truncate
  // ...
});
```

## What is fenced

- **Every tool result**, success, error and defect alike (an upstream error can
  echo a page title), except tools on the `trusted` allowlist. Unlisted tools,
  MCP tools, `bash`, `recall` and `task` are all fenced by default. The plugin
  never inspects output to decide: a result containing a fence-shaped string is
  wrapped like any other. `selfFenced` names tools that wrap their own output
  (`fence.fenceFor(runId)`); their errors are still wrapped.
- **Stored copies.** The truncate plugin stores oversized results with their
  provenance (`trusted`, producing tool, run), keyed by (run, tool-use id) with a
  suffixed handle when a backend repeats an id (`call_0`, `call_0~2`).
  `show_tool_result` returns that provenance in the same result as the content,
  and the plugin returns the slice raw only if it says trusted **and** the
  producing tool is on the fence plugin's allowlist. A missing flag, another run's
  entry or a legacy entry reads as untrusted. Two lists that disagree resolve to
  untrusted.
- **The compaction summary.** It is derived from untrusted text and re-enters the
  conversation as a user message, so it is fenced; the summariser also gets the
  fence note in its system prompt.
- **Memory.** Entries carry a `trusted` flag, absent by default (model-written
  memory inherits what the model read). The untrusted entries of the memory index
  in the system prompt are fenced; `recall` is a tool, so it is fenced too. Set
  `trusted: true` only on entries the operator wrote.
- **Subagents.** The plugin is inherited by every subagent run (`inheritToSubagents`)
  with that run's own nonce, and a `task` result is fenced in the parent.

Plugin order does not decide safety; list the fence after truncate so the
truncated head and its marker are fenced too.

## Nonces and resume

Each run, and each subagent run, has its own nonce, kept in a `NonceStore`
(`untrustedResultsPlugin({ nonces })`; default: in memory). A resumed run in the
same process keeps its nonce, so history fenced before the pause still matches the
note. Across processes, pass a store backed by your own storage. Resuming a run
whose nonce the plugin cannot recover is **refused** (a `PluginError` from
`assertResumable`), because the restored history would carry fences that name the
old nonce while the note names a new one. The in-memory store keeps the 10,000 most
recently used runs, so a live run does not lose its nonce.

## What the fence does to text

| Input | Result |
|---|---|
| `</untrusted-data-NONCE>` in the text | `<` and `>` escaped as `<` / `>`; the block cannot be closed |
| the nonce itself in the text | replaced by `[nonce]` |
| fullwidth brackets (`＜`) | NFKC turns them into ASCII first, then escaped |
| guillemets, math and CJK brackets, `˂˃`, `⟪⟫`, `⦉⦊`, ornaments (`LOOKALIKE_BRACKETS`) | visible `[U+XXXX]` placeholder |
| zero-width, bidi override, control characters | space (newline and tab kept) |
| variation selectors, Mongolian FVS, U+034F, Hangul fillers, U+2028, U+2029 (`INVISIBLE_RANGES`) | space (U+2028/2029: newline) |
| a lone surrogate half | U+FFFD (some providers reject a request that carries one) |
| very long strings, huge arrays, deep objects | bounded (`maxFieldChars`, default 2000; 2000 items; 500 keys; depth 12; no lone surrogate left by a cut) |

The two tables are exported and tested one code point at a time. `wrap(section, body)`
takes a string or any JSON-able value; `wrapText` is the whole-text variant.

## What it does not do

- **Trust is per tool, so it can launder.** A trusted `read_file`, `bash` or
  `grep` returns raw text that the agent wrote earlier from fenced web content,
  or that a download put on disk. "Derived stays untrusted" does not hold across
  the filesystem. Do not trust filesystem or shell tools unless the sandbox is
  read-only and holds only the operator's own files. `task`, `recall`,
  `show_tool_result` and `skill_load` carry derived text, so listing one in
  `trusted` throws at construction.
- **Persistence channels.** Instruction files (`loadInstructionFiles`, read from
  the working directory) and skill names and descriptions go into the system
  prompt unfenced: they are treated as the operator's. Any tool that can write
  under the working directory can plant text there for the next run. The markdown
  memory adapter ignores `trusted: true` in a file's frontmatter unless it was
  opened with `allowTrustedFrontmatter: true`, for the same reason.
- **Tool descriptions.** MCP tool descriptions (server-supplied) are cleaned and
  bounded to 500 characters before the model sees them, but are not fenced; only
  connect servers you would run code from.
- **Harness-made tool errors.** Errors produced outside a tool's `execute`
  (argument-validation errors that echo arguments, unknown-tool text,
  `beforeToolCall` deny reasons, output-schema retry feedback) are not fenced.
  They are authored by the model or the operator, but may quote their input.
- **Text a host adds** through `appendMessages` or builds into prompts itself.
- **Stored overflow.** The truncate store never evicts (use a short-lived process
  or your own store). An entry stored without run metadata (a legacy `set()`
  call) can be read by any run, always as untrusted. If the fence plugin is listed
  before truncate, a truncated head can cut inside a fence and leave it unclosed
  (still data, never trusted).

A fence lowers the odds that injected text steers the model. It does not make the
text safe. Keep the tools of an agent that reads outside text unable to do harm
(read-only, or a draft store a validator checks), set budgets, and treat everything
the model proposes to write as untrusted too.
